---
title: "Installer la CLI"
description: "Compilez la CLI Syntheo depuis les sources et reliez-la à vos données locales."
---

La commande `syntheo` regroupe la CLI et le serveur MCP local. Elle lit la base SQLite de l'application de bureau, sur votre ordinateur.

## Disponibilité

<Warning>
  La CLI n'est pas incluse dans les paquets publiés (AppImage, `.deb`, `.exe`, `.msi`) et n'est pas publiée comme binaire séparé dans les GitHub Releases. Pour l'instant, compilez-la depuis les sources.
</Warning>

Dans l'application, **Paramètres → Développeurs → CLI & MCP**, la ligne « Syntheo CLI » propose un bouton « Installer ». Sur les versions publiées, ce bouton reste inactif, car la CLI n'est pas embarquée. Le bouton « Copier la configuration » du « Serveur MCP » reste lui aussi inactif dans ce cas : écrivez la configuration vous-même (voir [MCP pour les agents](/agents/mcp)).

## Compiler depuis les sources

Prérequis : [Rust](https://rustup.rs) installé avec `rustup`. Le dépôt fixe sa version de la chaîne d'outils dans `rust-toolchain.toml` ; `rustup` la télécharge automatiquement.

```bash
git clone https://github.com/WillIsback/syntheo-desktop.git
cd syntheo-desktop
cargo install --locked --path apps/cli
~/.cargo/bin/syntheo --version
```

`cargo` installe l'exécutable `syntheo` dans `~/.cargo/bin` (`%USERPROFILE%\.cargo\bin` sous Windows). Ajoutez ce dossier à votre `PATH` si votre terminal ne trouve pas la commande.

<Warning>
  Le paquet `.deb` installe l'application de bureau sous le nom `/usr/bin/syntheo`. Sur une machine où le `.deb` est installé, `syntheo` peut donc lancer l'application au lieu de la CLI, selon l'ordre de votre `PATH`. Vérifiez avec `which -a syntheo`. En cas de doute, appelez la CLI par son chemin absolu, `~/.cargo/bin/syntheo`, en particulier dans la configuration de vos clients MCP.
</Warning>

Pour mettre à jour la CLI, récupérez les dernières sources (`git pull`) et relancez la commande `cargo install`. Gardez la CLI et l'application au même niveau de version : la CLI ne migre jamais la base.

## Relier la CLI à vos données

Ouvrez l'application une fois pour qu'elle crée sa base. Ensuite, la CLI et le serveur MCP fonctionnent même application fermée, sauf pour l'import d'enregistrement, qui exige l'application ouverte.

Sans option, la CLI cherche `app.db` dans le dossier de données de votre système :

| Système | Emplacement par défaut |
| --- | --- |
| Linux | `~/.local/share/syntheo/app.db`, puis `~/.local/share/fr.willisback.syntheo/app.db` |
| Windows | `%APPDATA%\syntheo\app.db`, puis `%APPDATA%\fr.willisback.syntheo\app.db` |

Pour une autre base, passez une option globale ou une variable d'environnement :

```bash
syntheo --db-path /chemin/vers/app.db --json meetings list
SYNTHEO_DB_PATH=/chemin/vers/app.db syntheo --json meetings list
syntheo --base /chemin/vers/dossier-syntheo --json meetings list
```

`--base` désigne un dossier qui contient `app.db`. `--db-path` est prioritaire sur `--base`.

Vérifiez ensuite la connexion :

```bash
syntheo --json doctor
```

## Accès en lecture et en écriture

Les lectures de réunions ouvrent la base en lecture seule. Les commandes `proposals create`, `proposals decline`, `meetings import` et `syntheo mcp` ouvrent la base en écriture, pour préparer ou refuser des modifications et pour créer une réunion importée. Aucune commande ne crée la base ni n'exécute de migration : c'est le rôle de l'application.
